# Who Gets You Context

This context defines the core language for the party game "Who Gets You?" so prompts, UI, and rules use the same terms.

## Language

**Shallow**:
A lightweight, realistic, low-pressure question style where players answer an everyday preference, habit, routine, taste, style, small joy, simple choice, or plausible "what if / what would you do" situation. The answer does not need to reveal a serious truth or personal story, but it should still sound like something the player would plausibly say, choose, or do in real life.
_Avoid_: Easy, casual

**Deep**:
A reflective, emotionally safe question style where the Storyteller's answer should reveal something personally true, such as a value, memory, relationship pattern, belief, regret, hope, or self-understanding.
_Avoid_: Serious mode, therapy mode

**Storyteller Answer**:
The answer submitted by the current Storyteller for the round. In Shallow it represents what the Storyteller would plausibly say or do; in Deep it represents something personally true about the Storyteller.
_Avoid_: True answer

**Suggested Answer**:
An AI-generated draft answer a player may use or edit. For Shallow it should be short, casual, realistic, and immediately playable; for Deep it should be first-person, personal, and emotionally safe.
_Avoid_: Correct answer, official answer

**Canonical Suggested Answer**:
The English version of a Suggested Answer generated by AI. It is translated into the room language before being shown to a player.
_Avoid_: Internal answer

**Random**:
A wildcard theme meaning no fixed life area. It appears after Named Themes and gives the AI permission to invent a surprising angle; in Shallow it should favor unexpected but realistic everyday topics, while in Deep it should still stay reflective and emotionally safe.
_Avoid_: Anything, no theme, default theme

**Named Theme**:
A theme with a recognizable life area, such as Work, Family, Love, or Travel. Shallow questions for a Named Theme should stay connected to that life area while staying realistic, light, and easy to answer.
_Avoid_: Category

**Question Angle**:
A non-player-facing sub-area inside one Theme and one Level that guides one generated question proposal, such as food and drink, communication style, daily routine, work focus, or friendship rituals. A Question Angle is narrower than a Theme and helps diversify questions without changing the selected Theme.
_Avoid_: Category, focus cue

**Question Angle Catalog**:
The curated set of allowed Question Angles for each Theme and Level. The Question Angle Catalog is the source of question-generation guidance; the AI may use a selected Question Angle, but it should not invent the angle list itself.
_Avoid_: Dynamic angle generation, category list

**Angle Repetition**:
The quality problem where generated questions vary their wording but keep returning to the same Question Angle, such as repeated food, snack, coffee, lunch, and dessert questions. Angle Repetition is distinct from exact question repetition.
_Avoid_: Duplicate question

**Angle History**:
The record of Question Angles already used for generated question proposals in a room or review session. Angle History supports diversity across later question generation, whether or not every proposal became the final Confirmed Question.
_Avoid_: Category memory

**Question Candidate**:
One generated question proposal tied to one Question Angle. A Question Candidate can be shown to the Storyteller, skipped, or edited before a Confirmed Question exists.
_Avoid_: Draft question

**Candidate Set**:
A ranked list of Question Candidates generated for a selected Theme and Level. When enough Question Angles are available, a Candidate Set should contain candidates from different Question Angles so changing the question changes the sub-area, not only the wording.
_Avoid_: Batch, alternatives

**Confirmed Question**:
The final question approved by the Storyteller for the round. Theme and level guide AI-generated questions, but the Storyteller may manually edit the Confirmed Question without validation.
_Avoid_: Validated question

**Canonical Question**:
The English version of the Confirmed Question. It is the stable question text used for generation history and prompt context, even when players see another language.
_Avoid_: Source question, internal question

**Display Question**:
The player-facing version of the Confirmed Question in the room language. If the Storyteller edits the Display Question, it is translated back into a Canonical Question when confirmed.
_Avoid_: Translated copy, localized question

**Question Edit**:
A Storyteller change to the Display Question before confirmation. In English rooms the edit becomes both Display Question and Canonical Question; in non-English rooms the edit is translated back into English to update the Canonical Question.
_Avoid_: Prompt edit, source edit

**Legacy Question**:
A question saved before Canonical Question and Display Question were separated. During an active round, a Legacy Question may be treated as both canonical and display text.
_Avoid_: Migrated question

**Question Translation**:
The process of converting between Canonical Question and Display Question. It is skipped when the room language is English and uses a fixed low-latency translation model when needed. Translation may make the Display Question natural and playable in the room language, but it must preserve the Canonical Question's intent.
_Avoid_: Regeneration, rewrite

**Suggested Answer Translation**:
The process of converting a Canonical Suggested Answer into the room language. Player-submitted final answers are not translated back into English.
_Avoid_: Answer normalization

**Guess Target**:
The answer listeners are trying to identify during guessing. The Guess Target is always the Storyteller Answer, regardless of whether the round is Shallow or Deep.
_Avoid_: Truth, correct answer

**Game Statistics**:
Aggregate facts computed from completed rounds and shown at Final Results after the whole game ends. Game Statistics explain patterns in play, such as guessing accuracy or misleading answers, but they are separate from scoring.
_Avoid_: Round summary, analytics

**Completed Round**:
A round whose answers have been revealed and scored. Game Statistics should use only Completed Rounds, not a round still in question selection, answer entry, or guessing.
_Avoid_: Current round, partial round

**Mind Reader**:
A Game Statistic for the player with the most correct listener guesses across Completed Rounds.
_Avoid_: Best guesser

**Wrong With Confident**:
A Game Statistic for the player with the fewest correct listener guesses among players who made listener guesses across Completed Rounds.
_Avoid_: Worst guesser, does not understand others

**Best Impostor**:
A Game Statistic for the player whose listener answers were selected by other listeners the most across Completed Rounds.
_Avoid_: Most misleading player

**404 Personality**:
A Game Statistic for the Storyteller whose Storyteller Answer was guessed correctly least often across Completed Rounds.
_Avoid_: Hardest Storyteller to guess

**No Incognito Mode**:
A Game Statistic for the Storyteller whose Storyteller Answer was guessed correctly most often across Completed Rounds.
_Avoid_: Most readable Storyteller

**Group Telepathy Score**:
A Game Statistic for the group's overall correct listener guesses divided by total listener guesses across Completed Rounds.
_Avoid_: Guess accuracy

**Certified Bestie**:
A Game Statistic for each player showing the listener or listeners who correctly guessed that player's Storyteller Answer most often when that player was Storyteller. If nobody guessed that player's Storyteller Answer correctly, the player has no Certified Bestie yet.
_Avoid_: Best friend, understands them most

**Statistic Tie**:
A Game Statistic result where multiple players share the same best value. Statistic Ties should show all tied players rather than choosing an arbitrary single winner.
_Avoid_: Tiebreak winner

**Shallow Humor Boundary**:
The safety boundary for AI-generated Shallow questions. Shallow should stay realistic and light; playful phrasing is allowed, but generated questions should avoid fantasy premises, childish framing, cruelty, forced embarrassment, private exposure, discriminatory framing, or sexual pressure.
_Avoid_: No boundary

## Example Dialogue

Developer: "Should Shallow questions ask players to tell a true story?"

Domain expert: "No. Shallow questions should be light and easy, like everyday preferences, habits, routines, small joys, or realistic what-would-you-do situations."

Developer: "Then what makes Deep different?"

Domain expert: "Deep keeps the personal-truth side of the game. It should invite real reflection without becoming heavy or unsafe."

Developer: "Should the UI ask listeners to find the true answer?"

Domain expert: "No. Say Storyteller Answer. In Shallow, the answer may be imagined, but it should still feel like the Storyteller."

Developer: "Can the code still use true internally?"

Domain expert: "Yes, but player-facing text and documentation should say Storyteller Answer."

Developer: "Should suggested answers use the same style for both levels?"

Domain expert: "No. Shallow suggestions should be quick and funny; Deep suggestions should stay personal and reflective."

Developer: "Should Suggested Answers also use canonical English?"

Domain expert: "Yes for AI-generated suggestions. Generate them in English, translate them for display, and leave player-submitted final answers in the room language."

Developer: "Should Random have a detailed theme description?"

Domain expert: "No. Keep it broad. Random should leave creative space while still following the chosen level."

Developer: "How do we stop Random or Named Themes from repeating the same kind of question?"

Domain expert: "Use a Question Angle. It keeps the selected Theme intact while rotating the specific sub-area of the question."

Developer: "Is repeating snacks, desserts, coffee, and lunch the same as repeating one question?"

Domain expert: "No. That is Angle Repetition: different wording, same kind of question."

Developer: "Should a generated proposal count in Angle History if the Storyteller later edits it?"

Domain expert: "Yes. It still consumed that Question Angle and should affect later diversity."

Developer: "When the Storyteller changes question, should the game ask for another wording of the same angle?"

Domain expert: "No. A Candidate Set should prefer different Question Angles so alternatives feel meaningfully different."

Developer: "Should the Storyteller choose the Question Angle?"

Domain expert: "No. The Storyteller chooses Theme and Level; Question Angle stays behind the scenes."

Developer: "If the Storyteller edits a generated question into another sub-area, should the Question Angle change?"

Domain expert: "No. The Question Angle describes the generated proposal, not a reclassification of the final edit."

Developer: "Can Shallow and Deep share the same Question Angle list?"

Domain expert: "No. A Question Angle belongs to one Theme and one Level because Shallow and Deep need different kinds of questions."

Developer: "Should the AI invent Question Angles during generation?"

Domain expert: "No. The Question Angle Catalog is curated so question diversity can be reviewed and tuned."

Developer: "Can a Shallow Work question be about anything light?"

Domain expert: "No. If the Storyteller picked Work, keep it recognizably about work, just make it light and realistic."

Developer: "Should we block a Storyteller from editing a Shallow question into something serious?"

Domain expert: "No. The AI should respect the level, but the Storyteller owns the final question."

Developer: "Which question should be used for repetition history?"

Domain expert: "Use the Canonical Question in English. Players see the Display Question in the room language."

Developer: "Do we still need a separate question refinement step?"

Domain expert: "No. Generate the Canonical Question in English, then let Question Translation handle natural player-facing phrasing when needed."

Developer: "Does Shallow need different scoring?"

Domain expert: "No. The target is still the Storyteller Answer; only the style of question changes."

Developer: "Are Game Statistics part of scoring?"

Domain expert: "No. They explain how the game unfolded after it ends; they do not change points."

Developer: "Should a half-finished round count in Game Statistics?"

Domain expert: "No. Only a Completed Round counts because it has revealed answers and scoring."

Developer: "Which Game Statistics should be shown first?"

Domain expert: "Start with Mind Reader, Wrong With Confident, Best Impostor, 404 Personality, No Incognito Mode, and Group Telepathy Score."

Developer: "What does it mean to understand a player most?"

Domain expert: "Use Certified Bestie: who correctly guessed that player's Storyteller Answer most often when that player was Storyteller."

Developer: "If multiple players tie for a Game Statistic, who should be shown?"

Domain expert: "Show all tied players. Game Statistics are playful summaries, not tiebreak scoring."

Developer: "Can Shallow questions be completely unrestricted?"

Domain expert: "No for AI generation. Shallow has no seriousness boundary, but generated humor still has a harm boundary."
