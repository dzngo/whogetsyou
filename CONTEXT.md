# Who Gets You Context

This context defines the core language for the party game "Who Gets You?" so prompts, UI, and rules use the same terms.

## Language

**Shallow**:
A lightweight, realistic, low-pressure question style where players answer an everyday preference, habit, routine, taste, style, small joy, simple choice, or plausible "what if / what would you do" situation. A Shallow question may be a generic poll and does not need to reveal a distinctive personal characteristic, but the answer should still be something the player could plausibly say, choose, or do.
_Avoid_: Easy, casual

**Deep**:
A reflective, emotionally safe question style where the Storyteller's answer should reveal something personally true, such as a value, memory, relationship pattern, belief, regret, hope, or self-understanding.
_Avoid_: Serious mode, therapy mode

**Storyteller Answer**:
The answer submitted by the current Storyteller for the round. In Shallow it represents what the Storyteller would plausibly say or do; in Deep it represents something personally true about the Storyteller.
_Avoid_: True answer

**Suggested Answer**:
An AI-generated draft answer a player may use or edit. For Shallow it should be short, casual, realistic, and immediately playable; for Deep it should be first-person, personal, and emotionally safe.
_Avoid_: Correct answer, official answer

**Canonical Suggested Answer**:
The English version of a Suggested Answer generated by AI. It is translated into the room language before being shown to a player.
_Avoid_: Internal answer

**Random**:
A wildcard theme meaning no fixed life area. Random is not a stored Theme Membership; it allows questions to be considered regardless of their Named Theme memberships while still respecting the selected Level.
_Avoid_: Anything, no theme, default theme

**Named Theme**:
A theme with a recognizable life area, such as Work, Family, Love, or Travel. Shallow questions for a Named Theme should stay connected to that life area while staying realistic, light, and easy to answer.
_Avoid_: Category

**Theme Membership**:
The classification that relates a Question Bank entry to one Named Theme. A question may have zero or more equal Theme Memberships; it has no primary Theme, and Random is never a Theme Membership.
_Avoid_: Primary theme, category tag, Random membership

**Question Angle**:
A legacy non-player-facing generation instruction inside one Theme and one Level, such as food and drink, communication style, or daily routine. Question Angles guide the current real-time generator but do not classify Question Bank entries.
_Avoid_: Question Aspect, category, focus cue

**Question Aspect**:
The single theme-independent subject or life facet explored by a Question Bank entry, such as meetings, unexpected free time, communication channels, or carrying traditions forward.
_Avoid_: Question Angle, Theme, category

**Question Perspective**:
The non-player-facing lens through which a question approaches its Question Aspect, such as preference, habit, reaction, memory, trade-off, aspiration, self-perception, social role, or hypothetical constraint. Questions can share an Aspect while using different Question Perspectives.
_Avoid_: Question Aspect, wording pattern

**Taxonomy Candidate**:
A proposed addition or change to the Question Aspect or Question Perspective taxonomy. It stays unusable by normal proposal agents until independent support, distinctness, counterexamples, and shadow classification admit it into a new Taxonomy Version.
_Avoid_: approved Question Aspect, generation hint

**Taxonomy Version**:
An immutable version of the approved Question Aspect and Question Perspective identities, names, definitions, examples, exclusions, aliases, and deprecations used to classify Question Revisions.
_Avoid_: editable tag list

**Semantic Scenario**:
The concrete situation, event, or condition posed by a Question Bank entry after wording is normalized, such as receiving an unexpected free hour or handling a chaotic meeting.
_Avoid_: Question Aspect, prompt

**Answer Space**:
The semantic kind of short answers a question invites, inferred from the question text rather than from simulated answers, such as activities, foods, communication channels, or group roles.
_Avoid_: Suggested Answers, generated answers

**Wording Pattern**:
The linguistic form of a question independently of its meaning, such as a situational `what do you do first` frame or a forced choice.
_Avoid_: Semantic Scenario, Question Perspective

**Semantic Repeat**:
The bank-quality conflict where two questions substantially overlap in Semantic Scenario, Question Perspective, and Answer Space. A shared Question Aspect or Wording Pattern alone does not make questions Semantic Repeats.
_Avoid_: exact duplicate, shared topic, similar wording

**Bounded Openness**:
A question quality where the prompt is concrete enough to invite a short, immediate answer while leaving room for different players to answer differently.
_Avoid_: Generic question, narrow question

**Question Quality Floor**:
The minimum trust contract for a Question Bank entry: it is clear, answerable, emotionally safe, correct for its Level, personally revealing when Deep, and not a semantic repeat of the bank. Taxonomy completeness, abstract coverage, and evaluator consensus are not part of the Question Quality Floor.
_Avoid_: quality score, taxonomy completeness, coverage target

**Question Angle Catalog**:
The legacy curated set of Question Angles for each Theme and Level used by the current real-time generator. It may seed future proposal work but is not the Question Bank's classification taxonomy.
_Avoid_: Dynamic angle generation, category list

**Question Bank**:
A large reusable collection of full English questions, each with exactly one Level and zero or more Theme Memberships. It stores full questions, unlike the Question Angle Catalog, which stores sub-areas that guide questions.
_Avoid_: Question Angle Catalog, prompt library

**Question Revision**:
One immutable version of a trusted Question Bank entry. A stable Question ID may have multiple Question Revisions, but only one revision is current in a given Question Bank Snapshot; changing a revision never overwrites its history.
_Avoid_: Question Candidate, mutable question row

**Staged Question**:
A trusted question that has passed the Question Quality Floor but is not yet part of a Question Bank Release. Its classification metadata may still be pending without weakening the trust in its question text.
_Avoid_: Question Candidate, published question

**Question Bank Snapshot**:
An immutable, versioned selection of exact Question Revisions and taxonomy definitions. A snapshot makes evaluation and later gameplay integration reproducible even after questions are corrected or retired.
_Avoid_: live query result, Question Bank

**Question Bank Release**:
The atomic publication of one verified Question Bank Snapshot as the current trusted corpus. A release records its gates and may later be rolled back or marked Withdrawn without mutating the snapshot.
_Avoid_: deployment of the enrichment pipeline, mutable bank

**Release Spot Check**:
The bounded human inspection of a deterministic sample of otherwise accepted questions and their most suspicious neighbours before a Question Bank Release. Its reviewed questions consume the production campaign's protected human-review slots.
_Avoid_: full-bank revalidation, random informal review

**Legacy Coverage Region**:
A retired bootstrap-generation target from version 1. Version 2 does not create, classify, review, or complete Coverage Regions; the 418 unresolved legacy cases remain audit-only in the Legacy Archive.
_Avoid_: current generation target, human-review input, release requirement

**Legacy Coverage Plan**:
A retired version-1 plan built from Coverage Regions. Version 2 replaces it with local Observed Diversity Feedback computed only after questions are staged.
_Avoid_: bootstrap prerequisite, current pipeline state, generation quota

**Diversity Feedback**:
A compact advisory summary of repeated patterns observed in Staged Questions and released Question Revisions. It may encourage later creative batches to explore different semantic territory but never creates quotas or admission requirements.
_Avoid_: Coverage Plan, generation target, quality gate

**Bootstrap Enrichment**:
The initial construction of a Question Bank by generating and evaluating concrete questions before deriving coverage guidance from the accepted corpus.
_Avoid_: Coverage Plan generation, taxonomy matrix completion

**Enrichment Budget**:
The explicit maximum worst-case list-price exposure that the Question Enrichment Pipeline may authorize for one run, together with its provider-attempt allowance. It is an application safety contract rather than a promise that the provider invoice will equal the ledger. Reaching it stops new model work without weakening the Question Quality Floor.
_Avoid_: exact invoice guarantee, advisory estimate, unlimited retry allowance

**Budget Reservation**:
The worst-case list-price amount atomically held from an Enrichment Budget before one provider attempt is sent. A successful response reconciles the reservation against native provider usage; a cached application result needs no reservation.
_Avoid_: provider spend cap, estimated invoice after the call

**Unknown Spend**:
A Budget Reservation retained after a timeout, crash, transport ambiguity, unexpected model identity, or other outcome whose billable usage cannot be safely reconciled. Unknown Spend continues to consume the Enrichment Budget until authoritative evidence resolves it.
_Avoid_: zero-cost failure, automatic retry allowance

**Question Enrichment Pipeline**:
The automated process that grows and maintains the Question Bank by proposing, challenging, evaluating, deduplicating, and admitting Canonical Questions.
_Avoid_: Question generator, human review queue

**LLM Agent**:
One isolated, role-specific model invocation inside the Question Enrichment Pipeline, with a versioned prompt, limited context, structured input, and structured output. An LLM Agent has no hidden memory between runs and cannot directly mutate trusted Question Bank or Taxonomy state.
_Avoid_: persistent persona, deterministic Module

**Agent Configuration**:
The versioned execution contract for one LLM Agent role, including model identity, reasoning effort, prompts, schemas, context policy, rubric or taxonomy version, timeout, and retry limit.
_Avoid_: untracked prompt, model alias alone

**Creative Strategy**:
One of four isolated Gemini agent missions—concrete life moments, relational mirrors, tensions/trade-offs, or inner signals. Each agent returns exactly five finished question texts with no Theme or classification metadata.
_Avoid_: Coverage Region, prewording concept, taxonomy quota

**Question Provenance**:
The immutable ancestry and rights record for a question proposal or Question Bank entry, including its origin, transformations, responsible human or agent, model and policy versions, and license or consent evidence.
_Avoid_: Generation metadata, audit log

**Human Review Queue**:
The bounded collection of Review Packets for concrete question-specific uncertainty that remains after automated escalation. At most ten distinct questions per 200-question production campaign may receive human review; operational failures, abstract Coverage Regions, and speculative taxonomy combinations never enter the queue during Bootstrap Enrichment.
_Avoid_: Question Bank, rejected questions, failure log, coverage backlog

**Review Packet**:
The consolidated, versioned question text and concise evidence a human needs to resolve every reviewable uncertainty known for one question. Multiple uncertainties for the same question consume one human-review slot.
_Avoid_: provider error report, evaluator transcript, separate case per uncertainty

**Evaluation Evidence**:
The versioned structured record showing how a question proposal passed, failed, or remained uncertain at every required quality and semantic-repetition gate. It preserves deterministic findings, rubric results, selective escalation and relation evidence with concise reason codes, never private chain-of-thought.
_Avoid_: consensus score, evaluator transcript

**Admission Outcome**:
The immutable recorded result of deciding one question proposal: Accept, Reject, or Human review. An automatic Human review outcome may be followed by a human Accept or Reject outcome that references the original evidence and review resolution. Human review is an abstention, not a trusted Question Bank state; missing or uncertain automatic evidence can never directly produce Accept.

**Question Usage Metrics**:
Recorded facts about how Question Bank entries are shown and interacted with during play, including appearances, skips, edits, and confirmations. Question Usage Metrics are collected for future analysis but do not currently influence the Question Bank.
_Avoid_: Game Statistics, adaptive retrieval

**Question Usage Event**:
An append-only factual record that an exact Question Revision was presented, skipped, edited, confirmed, or used in a finished round. It uses game-scoped pseudonyms and never stores player-authored question text, answers, or guesses.
_Avoid_: Game Statistic, quality score

**Reference Examples**:
The frozen twelve-case human-reviewed set of good, bad, repetitive, and meaningfully different questions used to regress one exact evaluator configuration. Reference Examples are calibration evidence, never proposal source material or whole-bank release revalidation.
_Avoid_: training corpus, proposal examples

**Aspect Repetition**:
The bank-quality problem where questions vary their wording but keep returning to the same Question Aspect, such as repeated food, snack, coffee, lunch, and dessert questions. Aspect Repetition is distinct from exact wording and from a full semantic repeat.
_Avoid_: Angle Repetition, duplicate question

**Angle History**:
The record of Question Angles already used for generated question proposals in a room or review session. Angle History supports diversity across later question generation, whether or not every proposal became the final Confirmed Question.
_Avoid_: Category memory

**Question Candidate**:
One generated question proposal tied to one Question Angle. A Question Candidate can be shown to the Storyteller, skipped, or edited before a Confirmed Question exists.
_Avoid_: Draft question

**Candidate Set**:
A ranked list of Question Candidates generated for a selected Theme and Level. When enough Question Angles are available, a Candidate Set should contain candidates from different Question Angles so changing the question changes the sub-area, not only the wording.
_Avoid_: Batch, alternatives

**Confirmed Question**:
The final question approved by the Storyteller for the round. Theme and level guide AI-generated questions, but the Storyteller may manually edit the Confirmed Question without validation.
_Avoid_: Validated question

**Canonical Question**:
The English version of the Confirmed Question. It is the stable question text used for generation history and prompt context, even when players see another language.
_Avoid_: Source question, internal question

**Display Question**:
The player-facing version of the Confirmed Question in the room language. If the Storyteller edits the Display Question, it is translated back into a Canonical Question when confirmed.
_Avoid_: Translated copy, localized question

**Question Edit**:
A Storyteller change to the Display Question before confirmation. In English rooms the edit becomes both Display Question and Canonical Question; in non-English rooms the edit is translated back into English to update the Canonical Question.
_Avoid_: Prompt edit, source edit

**Legacy Question**:
A question saved before Canonical Question and Display Question were separated. During an active round, a Legacy Question may be treated as both canonical and display text.
_Avoid_: Migrated question

**Question Translation**:
The process of converting between Canonical Question and Display Question. It is skipped when the room language is English and uses a fixed low-latency translation model when needed. Translation may make the Display Question natural and playable in the room language, but it must preserve the Canonical Question's intent.
_Avoid_: Regeneration, rewrite

**Suggested Answer Translation**:
The process of converting a Canonical Suggested Answer into the room language. Player-submitted final answers are not translated back into English.
_Avoid_: Answer normalization

**Guess Target**:
The answer listeners are trying to identify during guessing. The Guess Target is always the Storyteller Answer, regardless of whether the round is Shallow or Deep.
_Avoid_: Truth, correct answer

**Game Statistics**:
Aggregate facts computed from completed rounds and shown at Final Results after the whole game ends. Game Statistics explain patterns in play, such as guessing accuracy or misleading answers, but they are separate from scoring.
_Avoid_: Round summary, analytics

**Completed Round**:
A round whose answers have been revealed and scored. Game Statistics should use only Completed Rounds, not a round still in question selection, answer entry, or guessing.
_Avoid_: Current round, partial round

**Mind Reader**:
A Game Statistic for the player with the most correct listener guesses across Completed Rounds.
_Avoid_: Best guesser

**Wrong With Confident**:
A Game Statistic for the player with the fewest correct listener guesses among players who made listener guesses across Completed Rounds.
_Avoid_: Worst guesser, does not understand others

**Best Impostor**:
A Game Statistic for the player whose listener answers were selected by other listeners the most across Completed Rounds.
_Avoid_: Most misleading player

**404 Personality**:
A Game Statistic for the Storyteller whose Storyteller Answer was guessed correctly least often across Completed Rounds.
_Avoid_: Hardest Storyteller to guess

**No Incognito Mode**:
A Game Statistic for the Storyteller whose Storyteller Answer was guessed correctly most often across Completed Rounds.
_Avoid_: Most readable Storyteller

**Group Telepathy Score**:
A Game Statistic for the group's overall correct listener guesses divided by total listener guesses across Completed Rounds.
_Avoid_: Guess accuracy

**Certified Bestie**:
A Game Statistic for each player showing the listener or listeners who correctly guessed that player's Storyteller Answer most often when that player was Storyteller. If nobody guessed that player's Storyteller Answer correctly, the player has no Certified Bestie yet.
_Avoid_: Best friend, understands them most

**Statistic Tie**:
A Game Statistic result where multiple players share the same best value. Statistic Ties should show all tied players rather than choosing an arbitrary single winner.
_Avoid_: Tiebreak winner

**Shallow Humor Boundary**:
The safety boundary for AI-generated Shallow questions. Shallow should stay realistic and light; playful phrasing is allowed, but generated questions should avoid fantasy premises, childish framing, cruelty, forced embarrassment, private exposure, discriminatory framing, or sexual pressure.
_Avoid_: No boundary

## Example Dialogue

Developer: "Should Shallow questions ask players to tell a true story?"

Domain expert: "No. Shallow questions should be light and easy, like everyday preferences, habits, routines, small joys, or realistic what-would-you-do situations."

Developer: "Then what makes Deep different?"

Domain expert: "Deep keeps the personal-truth side of the game. It should invite real reflection without becoming heavy or unsafe."

Developer: "Should the UI ask listeners to find the true answer?"

Domain expert: "No. Say Storyteller Answer. In Shallow, the answer may be imagined, but it should still feel like the Storyteller."

Developer: "Can the code still use true internally?"

Domain expert: "Yes, but player-facing text and documentation should say Storyteller Answer."

Developer: "Should suggested answers use the same style for both levels?"

Domain expert: "No. Shallow suggestions should be quick and funny; Deep suggestions should stay personal and reflective."

Developer: "Should Suggested Answers also use canonical English?"

Domain expert: "Yes for AI-generated suggestions. Generate them in English, translate them for display, and leave player-submitted final answers in the room language."

Developer: "Should Random have a detailed theme description?"

Domain expert: "No. Keep it broad. Random is a wildcard rather than a Theme Membership, and it still follows the chosen Level."

Developer: "Can one Question Bank entry belong to both Work and Hobbies?"

Domain expert: "Yes. Give it equal Theme Memberships for both; do not force one to be primary."

Developer: "How do we stop Random or Named Themes from repeating the same kind of question?"

Domain expert: "Use a Question Angle. It keeps the selected Theme intact while rotating the specific sub-area of the question."

Developer: "If two questions are both about meetings, are they necessarily repetitive?"

Domain expert: "No. One might ask about a preference and another about the Storyteller's social role. They share a subject but use different Question Perspectives."

Developer: "Why is 'What makes you happy?' weaker than asking which small part of a routine improves your mood?"

Domain expert: "The second question has Bounded Openness: it gives the player a concrete place to begin without forcing everyone toward the same answer."

Developer: "Is repeating snacks, desserts, coffee, and lunch the same as repeating one question?"

Domain expert: "No. In the Question Bank that is Aspect Repetition: different wording, the same theme-independent subject area."

Developer: "Should a generated proposal count in Angle History if the Storyteller later edits it?"

Domain expert: "Yes. It still consumed that Question Angle and should affect later diversity."

Developer: "When the Storyteller changes question, should the game ask for another wording of the same angle?"

Domain expert: "No. A Candidate Set should prefer different Question Angles so alternatives feel meaningfully different."

Developer: "Should the Storyteller choose the Question Angle?"

Domain expert: "No. The Storyteller chooses Theme and Level; Question Angle stays behind the scenes."

Developer: "If the Storyteller edits a generated question into another sub-area, should the Question Angle change?"

Domain expert: "No. The Question Angle describes the generated proposal, not a reclassification of the final edit."

Developer: "Can Shallow and Deep share the same Question Angle list?"

Domain expert: "No. A Question Angle belongs to one Theme and one Level because Shallow and Deep need different kinds of questions."

Developer: "Should the AI invent Question Angles during generation?"

Domain expert: "No. The Question Angle Catalog is curated so question diversity can be reviewed and tuned."

Developer: "Is the Question Bank another name for the Question Angle Catalog?"

Domain expert: "No. The Question Angle Catalog contains sub-areas that guide generation; the Question Bank contains reusable full Canonical Questions."

Developer: "If a bank question belongs to Work, Hobbies, and Goals, does it need three Question Angles?"

Domain expert: "No. It receives one global Question Aspect. Question Angles remain Theme-owned instructions for the legacy real-time generator."

Developer: "Does every new Question Bank entry need a person to approve it?"

Domain expert: "No. The Question Enrichment Pipeline is automated, so its evaluation and admission decisions must be reliable without per-question human review."

Developer: "What happens when the agents cannot confidently admit or reject a proposal?"

Domain expert: "Put it in the Human Review Queue with the agents' judgments, disagreements, and uncertainty evidence."

Developer: "Should four creative agents each write a question immediately?"

Domain expert: "Yes. Each isolated Gemini creative agent returns five finished question texts for its assigned Creative Strategy. It does not create concepts, assign Themes, inspect sibling output, or decide admission; deterministic preflight and semantic Modules handle overlap afterward."

Developer: "If an agent rewrites an externally sourced question, can the new wording drop the source record?"

Domain expert: "No. Question Provenance follows every rewrite; paraphrasing does not erase ancestry or rights obligations."

Developer: "Are question skips and edits part of Game Statistics?"

Domain expert: "No. They are Question Usage Metrics. We record them for future analysis, but they do not currently change the Question Bank."

Developer: "Do humans need to review every question so the agents know what good means?"

Domain expert: "No. Confirm a small set of Reference Examples once, send only uncertain questions to the Human Review Queue, and spot-check accepted questions occasionally."

Developer: "Should the evaluation agents discuss a proposal until they agree?"

Domain expert: "No. The routine GPT quality agent returns structured Evaluation Evidence. Only uncertain records receive one high-reasoning escalation; remaining uncertainty goes to the Human Review Queue instead of being hidden by consensus."

Developer: "What if an evaluator fails or its evidence is missing?"

Domain expert: "The Admission Outcome cannot be Accept. Do not retry automatically or turn an operational failure into human review; preserve completed work and continue only in a separately authorized run."

Developer: "Can we update the text of an active bank question in place?"

Domain expert: "No. Create a new Question Revision, evaluate the exact new text, and include it in a later Question Bank Snapshot. Old snapshots keep the old revision."

Developer: "Can a new Question Aspect generate its own proof that it is useful?"

Domain expert: "No. A Taxonomy Candidate must explain independently created classification gaps before it becomes available to proposal agents in a later Taxonomy Version."

Developer: "Is a huge raw question count enough to call the Question Bank complete?"

Domain expert: "No. Bootstrap release requires at least 200 eligible questions, complete quality and semantic evidence, a full-bank repetition scan, metadata completeness and anti-collapse gates, the frozen regression, and the protected release spot check. Legacy Coverage Regions are not a completion gate."

Developer: "If a bank release is bad, should we edit its questions in place?"

Domain expert: "No. Roll back to an earlier Question Bank Snapshot or release a corrected new snapshot. Released manifests and Question Revisions stay immutable."

Developer: "Can question skips automatically make the enrichment agents retire a bank question?"

Domain expert: "No. A Question Usage Event is stored for possible future study, but Question Usage Metrics have no read path into the bank or retrieval in this effort."

Developer: "Is the Question Enrichment Pipeline actually a multi-agent LLM system?"

Domain expert: "Yes. Four isolated Gemini LLM Agents propose questions, while separate GPT LLM Agents evaluate quality, resolve ambiguous semantic relations, and assign metadata. Deterministic Modules orchestrate them and alone control budgets, admission, identity, lifecycle, and release."

Developer: "Did semantic-routing-v5 replace the multi-agent architecture?"

Domain expert: "No. It makes local evidence authoritative for clearly different pairs, then sends each candidate's strongest ambiguous neighbour and any strong lexical alerts to the semantic GPT Agent. Creative, quality, semantic-escalation, and metadata roles remain separate."

Developer: "If one semantic GPT batch is truncated, should every quality-passing question in the production batch be discarded?"

Domain expert: "No. Preserve local passes and complete relation evidence. Only candidates whose admission depends on the failed or unsent semantic chunk become operationally unresolved, and they remain available for explicit reprocessing without another creative call."

Developer: "How does the semantic GPT Agent avoid saying a pair is distinct while labeling Scenario, Perspective, and Answer Space as overlapping?"

Domain expert: "Semantic-routing-v5 sends explicit dimension definitions and the deterministic repeat rule, and bounds high-reasoning work to six pairs per call. The verdict must agree with the three primary labels; genuine uncertainty abstains instead of producing contradictory evidence."

Developer: "Can a Shallow Work question be about anything light?"

Domain expert: "No. If the Storyteller picked Work, keep it recognizably about work, just make it light and realistic."

Developer: "Should we block a Storyteller from editing a Shallow question into something serious?"

Domain expert: "No. The AI should respect the level, but the Storyteller owns the final question."

Developer: "Which question should be used for repetition history?"

Domain expert: "Use the Canonical Question in English. Players see the Display Question in the room language."

Developer: "Do we still need a separate question refinement step?"

Domain expert: "No. Generate the Canonical Question in English, then let Question Translation handle natural player-facing phrasing when needed."

Developer: "Does Shallow need different scoring?"

Domain expert: "No. The target is still the Storyteller Answer; only the style of question changes."

Developer: "Are Game Statistics part of scoring?"

Domain expert: "No. They explain how the game unfolded after it ends; they do not change points."

Developer: "Should a half-finished round count in Game Statistics?"

Domain expert: "No. Only a Completed Round counts because it has revealed answers and scoring."

Developer: "Which Game Statistics should be shown first?"

Domain expert: "Start with Mind Reader, Wrong With Confident, Best Impostor, 404 Personality, No Incognito Mode, and Group Telepathy Score."

Developer: "What does it mean to understand a player most?"

Domain expert: "Use Certified Bestie: who correctly guessed that player's Storyteller Answer most often when that player was Storyteller."

Developer: "If multiple players tie for a Game Statistic, who should be shown?"

Domain expert: "Show all tied players. Game Statistics are playful summaries, not tiebreak scoring."

Developer: "Can Shallow questions be completely unrestricted?"

Domain expert: "No for AI generation. Shallow has no seriousness boundary, but generated humor still has a harm boundary."
